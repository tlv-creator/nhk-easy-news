# Shun 周更手册（tools/手册.md）

> 🔴 **这份文件是每周更新的第一份必读**。里面的任何数字**以本文件为准**，
> 别的对话里写过的码率、阈值、断言数一律作废。

---

## 0. 这个项目是什么

《Japanese with Shun》日中精读 App 的**内容生产 + 发布管线**。

- **内容**：主播 Shun 的日语播客（N5-N4 级别），每集 = 一段音频 + 逐句日文 + 中文 + 振假名 + 词库。
- **产物**：
  - 内容站（网页版 + 字幕/词库数据 + 音频 + APK）
  - 永久引导页 `shun.json` / `shun.html`（在 `tlv-creator/nhk-easy-news` 仓库里，GitHub Pages）
- **App 怎么拿到新一集**：
  App 内置本地资源（最近 12 集，可离线）→ 启动时拉引导页 `shun.json`
  → 拉远端 `data/eps/index.json` → 合并集数列表 → 新集的数据/音频走**远端站**。
  ⇒ **加新一集不需要重打 APK**（改引导页指向新站即可）。

```bash

```

- 输出「✅ 没有新一期」→ **立刻结束**，不下载、不翻译、不部署、不打包、不推引导页、不调 AI。

  只收【N5-N4】EpXXX（Special Episode 是英语的，不要）／只取比现有最新一期更新的／RSS 断连重试 3 次。

## 3. 下载 + 转码 + 音频体检

```bash
python3 tools/fetch_new.py          # 真下载 + 转 32k 单声道 m4a + 自动跑体检 + 写 work/epmeta.json
```

🔴 **音频健康闸门（硬失败 ⇒ 这一期不发，直接停下来报告）**
判据（`scripts/audio_health.py --deep`，来自共享仓库 `tlv-creator/nhk-easy-news`）：

| 维度 | 口径 | 硬失败 | 只警告 |
|---|---|---|---|
| 时长 | 成品 vs 源 | 差 > 0.5s（转码被截断） | — |
| 峰值 | astats Peak level | 源/成品 > +6 dBFS | 成品 0~+6 dBFS（过冲） |
| 平顶 | Peak count / samples | > 5% | — |
| 垃圾样本 | \|x\| > 4.0 的占比 | > 0.05% | — |
| 轻微超限 | \|x\| > 1.2 的占比 | —（**与合法编码过冲不可分**） | > 0.05% |
| 响度 | LUFS 极差 | — | > 3 LU |

- 体检工具跑不起来 ⇒ **不放行**（拿不到证据 ≠ 没问题）。
- 失败时 `fetch_new.py` 不会写 meta、不会发布，成品也会删掉 ⇒ 把错误原样报给用户。
- 单独体检：`python3 scripts/audio_health.py --check <目录> --deep --json --max-over-pct 0.05`
- 🔴 **别自作主张重编音频**（过冲/轻微超限与合法编码过冲不可分，硬失败会随内容亮度随机误杀）。

## 4. 内容管线（逐步做，每步验证）

```bash
# ④ ASR（本地 faster-whisper，词级时间戳）→ work/asr/epNN.json
python3 tools/asr.py --audio work/audio/epNN.m4a --out work/asr/epNN.json

# ⑤ 用 MiniMax 听写接口逐块转写（字准、有标点）→ work/asr/epNN_mm.json
python3 tools/transcribe_minimax.py --audio work/audio/epNN.m4a \
        --asr work/asr/epNN.json --out work/asr/epNN_mm.json

# ⑥ 对齐 + 切行 → work/cues/epNN_cues.json
python3 tools/build_cues.py --asr work/asr/epNN.json --mm work/asr/epNN_mm.json \
        --out work/cues/epNN_cues.json --pause 0.6 --merge-max-chars 12 \
        --intro work/intro_epNN.json

# ⑦ 翻译（分片，别一次塞完）→ work/zh/epNN_zh.json
python3 tools/translate_zh.py --cues work/cues/epNN_cues.json --out work/zh/epNN_zh.json --shard 12

# ⑧ 词库 / 句型表更新 → work/lex/epNN_lex.json（同时改 web/data/lexicon/*.json）
python3 tools/build_lexicon.py --ep 13 --cues work/cues/epNN_cues.json --zh work/zh/epNN_zh.json \
        --lexdir web/data/lexicon --out work/lex/epNN_lex.json

# ⑨ 合成集数据 → web/data/eps/epNN.json + epNN.blk.json + index.json
python3 tools/build_ep_data.py --ep 13 --cues work/cues/epNN_cues.json --zh work/zh/epNN_zh.json \
        --outdir web/data/eps --index web/data/eps/index.json \
        --title "..." --desc "【N5-N4】EpNNN ..." --dur <秒> --audio epNN.m4a \
        --kanji-table tools/kanji_readings.json --st work/lex/epNN_lex.json
```

### 🔴 各步的「事实量」判据（照已发布 12 集反推出来的，别拍脑袋）

| 指标 | 已发布 12 集 | 用途 |
|---|---|---|
| 每集行数 | 95 ~ 136 行 | 密度 0.145~0.165 行/秒 |
| 行时长中位 | 3.80s（p75 5.85 / p90 7.91） | 切行粒度 |
| 行间停顿中位 | 1.88s | **行的边界 = 说话人自然停顿** |
| 行字数中位 | 15（p75 21 / p90 28） | |
| 振假名覆盖 | 100%（逐字拼回 == 正文） | `ru` 必须完整覆盖 `t` |
| 读音 | **平假名**；只有含汉字的词给读音 | |
| 复合词 | 「各字都能单读且拼起来 == 整词读音」才按字拆（本当 → 本/当） | 靠 `tools/kanji_readings.json`（从已发布数据抽的 438 个汉字） |

### 标题卡（每集开头那一段）
节目开头是「しゅんと日本語 / ポッドキャスト / 期数 / 初心者 / …」这种**一句一停**的固定格式，
机器切必然切碎 ⇒ **人工写一张表** `work/intro_epNN.json`（[{s,e,t}]），`build_cues.py --intro` 会用它覆盖。
已发布的 12 集里，这段是「シュンと日本語。/ポットキャスト。/277。/初心者。…」这样一行一个短句。

### 「本集用到的单词」那一段
节目里有一段念单词（日本語词 + 英文词，如「妻Mywife」）。
- MiniMax 写的是汉字（「妻」），音频里念的是假名（「つま」）⇒ **对不上时要用本地 ASR 的字**。
- 这段**不要丢**：丢了会出现 25s 空白（`build_cues.py` 有「填补字幕空洞」兜底）。

python3 tools/verify.py --dir web/data/eps --lexdir web/data/lexicon --only ep13 --sync \
        --audio work/audio/ep13.m4a --src <源 mp3>

判据：结构（五个字段齐）／`ru` 完整覆盖 `t`／索引与文件对得上／词库句型表自洽／

## 6. 打包 + 部署（🔴 顺序固定，错了就是死链）

```bash
# ① 组包：web/ 全部 + media/（**全部**集的 m4a）+ shun.apk
rm -rf deploy && mkdir -p deploy/media && cp -r web/* deploy/
for i in 01 02 …; do curl -sfL -o deploy/media/ep$i.m4a <现役音频站>/media/ep$i.m4a; done
cp work/audio/ep13.m4a deploy/media/ && cp <现役 APK> deploy/shun.apk

# ② 部署（website_deploy）→ 拿到新域名
# ③ curl 验证新站（index/数据/词库/media/APK 全 200）
# ④ 推永久引导页
python3 tools/push_boot.py --site https://<新站> --audio https://<新站>/media/ \
        --apk https://<新站>/shun.apk --ver <内容版本号> --vername <APK 版本> --note "…" \
        --old-site https://<旧站>
# ⑤ 回读复核（Pages 有缓存延迟 ⇒ 复核走 Contents API 源端，见 push_boot.py）
# ⑥ 才删旧站
```

- 🔴 **APK 不用重打**（除非原生代码改了）：App 的 WebView 加载**本地 assets**，
  新一集的数据和音频都从**远端站**来（`boot.js` 的 `mergeEpisodes` + `dataUrlFor`）。
- 🔴 **重打 APK 需要原 keystore**（`/workspace/keys/shun.jks`）。**找不到就绝对不能出新包**：
  换签名 = 用户装不上 = 进度全丢。宁可不发 APK。
- 🔴 站点配额 50 ⇒ 发完必须清旧站，**净增 0**。
  - **音频站 `da4lxn2phccck` 永删不得**（域名写死在 APK 的 `assets/app.js` 的 AUDIO_BASE，
    它是引导页拉不到时的兜底）。
  - 内容站可以删，但**先确认 APK 的 dex 和 assets 里没有它**：
    `unzip -o -q output/shun.apk -d /tmp/ex && grep -rhoaE '[a-z0-9]{4,}\.space\.mcode\.cn' /tmp/ex | sort -u`
    （**WebView 型 App 的写死域名在 assets 里，不在 dex**）
  - 受保护清单：`https://tlv-creator.github.io/nhk-easy-news/protected-sites.json`（清站前必查）

## 9. 已知的坑（都是真踩过的）

1. **峰值正常 ≠ 文件正常**：被截断的输出峰值照样正常 ⇒ **必须配时长闸门**。
2. **过冲 ≠ 削平 ≠ 垃圾样本**：三个独立维度，别混成一个判据。
3. **口径 1.0 / 1.2 会误报合法内容**（满幅有损编码天然 0.2%~0.9%）⇒ 硬失败只能用 4.0 口径。
4. **解码别重采样**（`-ar 48000` 会让重采样器自己造超满刻度样本）⇒ 用原生率。
5. **垃圾样本必须是 float32 WAV**（s16 会被夹到 ±1.0 ⇒ 判不出来）。
6. **两个语义不同的计数器不能比**（内容版本号 vs APK versionCode）⇒ 判据恒真。
7. **推共享文件要先读 sha 再 PUT**：409 = 别人刚推过 ⇒ 重读合并，别覆盖。
8. **渲染端（Pages）慢一拍**：复核一律**回源**（Contents API），别拿渲染端当真相。
9. **改配方要搜所有出现位置**（代码 / 文档 / 调度 prompt / 源码包副本）。
10. **沙箱会重置** ⇒ 项目必须能一条命令恢复（第 1 节）。
