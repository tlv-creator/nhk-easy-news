# 新版「句子结构详解」设计（Shun）

> 本文件是这套注释的**唯一权威**。
> 任何代码、文档、调度 prompt 里出现的旧结构名（`blk` 的 MSVA 角色块、`ex-struct` 的 sg-row）
> 一律以本文件为准。

## 0. 目标形态（用户给的样例，逐字对齐）

```
一、大框架

[反対に] ［お金がたくさんあっても］ ［いい人間関係がなかったら］ 〈幸せを感じることが〉 （できません）
  连接          让步条件从句              条件从句                  宾语内容＋が          谓语

主句骨架：**［〜ことが］＋（できません）**＝"无法做到〜"。

层层修饰主句：
反対に → お金がたくさんあっても → いい人間関係がなかったら → 幸せを感じることが → できません

二、逐块拆解

第一块：反対に
- 接续词/副词，"相反地"。
- 修饰整个后句，表对比转折。

第二块：お金がたくさんあっても
【お金が】 [たくさん] （あっても）
  主语     程度副词   谓语（て形＋も）
...
意思：**"即使有很多钱"**。
```

### 结构要点（缺一不可）

1. **大框架**：一行分块，块用**四种括号**区分角色：
   - `[方]` ＝ 连接词 / 副词（独立成块）
   - `［方］` ＝ 从句（让步 / 条件 / 宾语从句 / 修饰从句 / 原因）
   - `〈方〉` ＝ 主句里的**宾语内容**（含形式名词化 `〜こと` + 后续助词）
   - `（方）` ＝ **谓语**（主句谓语、补助动词、句末语气）
   每块正下方对齐一个**角色标签**（中文短语，如「让步条件从句」「宾语内容＋が」「谓语」）。
2. **主句骨架**：一个公式，用同样的括号体系；带 `＝"中文释义"`。
3. **层层修饰主句**：箭头串，从最外层修饰到最内层，末端是主句谓语。
4. **逐块拆解**：每块一节，含
   - `块内骨架`：一行带括号的细分解（可为空 ⇒ 简单块）
   - `成分说明`：逐成分列表，每条讲「词性/语法功能 + 在这句里的具体作用」
   - `整块意思`：这块整体的中文意思
5. **整句意思**：最后一行。

## 1. 数据 schema（写进 `web/data/eps/epNN.json` 的每一行）

```jsonc
{
  "gs": {                       // grammar structure，新字段（可空）
    "frame": [                  // 大框架：按出现顺序的块
      { "s": "反対に", "b": "[]", "role": "连接" },
      { "s": "お金がたくさんあっても", "b": "［］", "role": "让步条件从句" },
      { "s": "いい人間関係がなかったら", "b": "［］", "role": "条件从句" },
      { "s": "幸せを感じることが", "b": "〈〉", "role": "宾语内容＋が" },
      { "s": "できません", "b": "（）", "role": "谓语" }
    ],
    "skel": "［〜ことが］＋（できません）",     // 主句骨架
    "skelMean": "无法做到〜",                    // 骨架的中文释义
    "chain": ["反対に", "お金がたくさんあっても", "いい人間関係がなかったら",
              "幸せを感じることが", "できません"],   // 层层修饰主句
    "blocks": [                 // 逐块拆解，与 frame 一一对应
      {
        "s": "反対に",                          // 块原文（逐字取自原句）
        "inner": "",                            // 块内骨架（可空）
        "parts": [                              // 成分说明
          { "s": "反対に", "note": "接续词/副词，\"相反地\"。修饰整个后句，表对比转折。" }
        ],
        "mean": "相反地"                          // 整块意思
      }
    ],
    "whole": "相反，即使有很多钱，如果没有良好的人际关系，就无法感到幸福。",
    "src": "llm"                                // 生成来源标记
  }
}
```

### 字段口径

- `frame[].s`：**必须逐字取自原句**（连续子串，不许改写、不许加读音括号）。
- `frame[].b`：只能是 `[]` `［］` `〈〉` `（）` 四种之一。
- `frame[].role`：中文角色短语，≤ 8 字。
- `blocks[i].s` 与 `frame[i].s` **必须相等**（一一对应，顺序一致）。
- `blocks[i].inner`：块内骨架，格式 `【A】 [B] （C）` 或空串。
- `blocks[i].parts[].s`：成分原文，**必须逐字取自该块**。
- `blocks[i].parts[].note`：1~2 句中文说明。
- `blocks[i].mean`：整块中文意思。
- `whole`：整句中文意思。

## 2. 硬性规则（写进 prompt，同时写进校验器）

1. **所有原文片段逐字取自原句** —— 校验器逐条 `in` 检查，抓到一条就整条丢弃重生成。
2. **不编造语法术语** —— 拿不准就写朴素说法。
3. **简单句就少拆** —— 主谓宾句不要硬造从句。
4. **不写例句**（本套注释自带上下文，不需要）。
5. **不用 emoji**，不要寒暄，不要复述题目。
6. **角色标签和括号必须配套**：`[]`↔连接/副词，`［］`↔从句，`〈〉`↔宾语内容，`（）`↔谓语。
7. `frame` 里的块**按出现顺序**且**拼起来能覆盖原句主干**（允许省略语气词等零碎）。
8. `parts[].note` 不许出现原文里没有的词形（防止模型自己造词）。

## 3. 为什么必须 LLM 离线生成

- 规则拼不出「让步条件从句」「て形＋も」「形式名词」「主句骨架公式」这一层语义。
- 现有 `tools/analyze.py` 的 `analyze_structure()` 只给出 MSVA 角色块（主语/谓语/宾语/状语/修饰/语气），
  精度差几个量级 ⇒ 不能复用。
- ⇒ **MiniMax-Text-01 离线批量生成 → 校验 → 内置进数据**。

## 4. 成本与降级

- 一次请求处理**一句**（句子短，批量塞多条会串味）。
- 断点续跑：`work/gs/epNN.json` 已有的句子跳过。
- 失败重试 3 次；仍失败 ⇒ 该句 `gs` 留空（前端不显示这一节）⇒ **不阻塞发布**。
- 校验不过 ⇒ 重生成；重试仍不过 ⇒ 留空并记录到 `work/gs/fail.log`。
