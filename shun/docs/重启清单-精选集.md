## 一、为什么是这 33 集

官方把播客按 **Genki 1 教材进度**编了号：`L1 自我介绍 → L2 智能手机 → L3 日常作息 → L4 昨天做了什么 → … → L23 高中时的事`。

这批集有三重好处：

1. **有教学顺序**（L2→L23 难度递增），不是按主题乱排；

2. **能对上教材**（Genki 1 课文场景），学完能直接用；

3. **单集短**（5–10 分钟，33 集共 3.9 小时），比「361 集全集」更可能被学完。

已排除：访谈/合作/特别节目（`Interview`/`Collab`/`Special`）26 集 —— 真实对话，难度虚高；以及与已上线 6 集题材重复的 8 集。

## 三、两条路：成本差 40 倍

| 路线 | 3.5 小时新音频 | token 消耗 | 说明 |
|---|---|---|---|
| **A. MiniMax ASR** | 3.5 h | **≈ 2.38 亿** | 按实测速率 6896 万 token/小时音频外推；一下吃掉 ¥49 套餐的 40% |

| **B. 平台通道** `connector__matrix__audios_understand` | 3.5 h | **0（不烧订阅额度）** | 一次调用同时产出「转写 + 中文翻译 + 结构化标注」；实测 61 秒音频约 6 秒出结果（实时率 0.1）⇒ 预计 **21 分钟**跑完 |

⇒ **建议走 B**：用 MiniMax 抽 1–2 集做质量对照（约 0.05 亿 token，可忽略），其余全走平台通道。


## 四、执行步骤（可直接照做）

```
① 拿 1 集（建议 L2 Smartphone，6 分钟）做样本验证：
   · 平台通道 audios_understand，prompt 写死「严格逐字转写；英文保持原样；不要添加原文没有的词；保留标点；看不清用 □」
   · 检查：转写是否逐字对得上？时间轴是否单调？
② 样本过了 → 切块送平台通道（长音频按 300s 切块，**时间轴必须加回块起点偏移**）
③ 产出统一成我的渲染契约：sents[i] = {t, ru, zh, gs{frame,blocks,skel,chain,whole}, s, e}
   · 注音用本地 ruby.py + kanjidic2（零额度）
   · 四类括号：[] 连接词/副词 ｜ ［］ 从句 ｜ 〈〉 宾语内容 ｜ （） 谓语
④ 过质量闸门：frame.s 逐字 ∈ 原句 ｜ 区间不重叠 ｜ 谓语块在末尾 ｜ 覆盖 ≥80%% ｜ 同类型相邻合并率 = 0
⑤ 按集懒加载落盘：shun-web/data/<tag>.json + index.json（首屏保持 ~28KB）
⑥ 推线上前：compare-and-swap（查 HEAD）→ 一次提交 → 推后回读 blob sha
```


## 五、已知坑（别再踩一遍）

- **平台通道会「意译改写」**：把「 Beginners」写成「ビギナーズ」、自己加 Genki level ⇒ prompt 必须写死逐字；它改完的文本实测比 MiniMax 词级拼接更准（MiniMax 会把「シュン」听成「旬」，44 集 ASR 里就有这个错）。

- **平台通道的时间轴是「相对它收到的那段音频」的** ⇒ 切块时必须加回块起点偏移（实测切块起点 300s 时，两路时间差中位 = 300.24s）。

- **推共享文件前先拉线上当基底 + CAS + 推后回读 sha**（本轮已踩：peer 覆盖了同名 `s001…s361`，结果虽好但是运气）。

- **别整目录推**：`index.json` 线上是 20 集版，本地 build 出来可能是 13 集版 ⇒ 整目录推会静默倒退。

- **`/tmp` 会被沙箱重启清空** ⇒ ruby 引擎、kanjidic2 等依赖要放 workspace（已在 `shun/tools/ruby/`）。


## 六、验收标准（沿用现有闸门）

- 浏览器断言：句子/四类括号/逐字注音/中文/弹窗四段/0 JS 报错（现 `verify_online3.py`）

- 数据闸门：`frame.s` 逐字 ∈ 原句、谓语块在末尾、覆盖 ≥80%、同类型相邻合并率 = 0

- 抽 3 集人眼过一遍：注音位置对不对、角色标签准不准、中文有没有错位

- 线上：先自己点一遍链接，再发
