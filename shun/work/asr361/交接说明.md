## 二、关键约定（换人接手必读）

1. **tag = `s001`…`s361`，按发布日期升序**（s001 = 最早的 Ep1，s361 = 最新的 Ep278）。
   ⇒ **天然是难度梯度**（最早的 Genki1 水平 → 最新的 N5-N4），也彻底绕开了旧项目「ep01=最新」的倒序坑。
   ⇒ 🔴 **2026-10-25 改名**：原为 `ep001`，与网页层同伴的 `ep01…ep13`（2 位）**字符串排序会混在一起**
     （"ep01" < "ep001" ⇒ 他的第 1 集会被插到我第 1、2 集中间）⇒ 改用 `s` 前缀（首字母不同 ⇒ 排序天然分离）。
   ⇒ 旧的 `ep*.json` 文件已改名为 `s*.json`，`tagmap.json` 里的 `tag` 字段同步改过。
2. **每集 2 个文件**：`asr/<uid>.json` + `mm/<uid>.json` 必须成对喂给 `build_cues.py`：
   ```
   python3 <shun>/tools/build_cues.py --asr asr/<uid>.json --mm mm/<uid>.json --out work/cues/<tag>_cues.json
   ```
3. **`asr` 文件的 `segments[].words[]` 字段不能少** —— `build_cues.py` 读的是 `seg["words"]`，不是 `seg["text"]`。少了会**静默切出空数组**（不报错）。
4. **音频直链**：`https://audio4.redcircle.com/episodes/<uuid>/stream.mp3`（uid 在 `tagmap.json` 里）。

## 三、怎么接着跑

### 3.1 只用现成 ASR（不花钱）
```bash
# 切句（纯 stdlib，不花额度）
bash tools/run_cues.sh
```

### 3.2 一条龙（平台通道，**零额度**）
```bash
python3 tools/prod.py --only ep361      # 单集
python3 tools/prod.py                    # 全量（361 集，约 1-1.5 小时）
```
产出 `prod/<tag>.json`，每句含 `s`/`e`/`ja`/`zh`/`frame`（四类括号成分）。
⚠️ 平台通道偶发失败 ⇒ 脚本内已带 3 次重试；`missing_blocks > 0` 的集要重跑。

### 3.3 补跑 ASR（**要额度**）
```bash
python3 tools/asr_minimax.py <uid...>    # 批量
python3 tools/asr_minimax.py             # 全部 361 集
```
⚠️ **切段偏移必须用精确 `-ss` 起点**（不能用 ffmpeg segment muxer 的累计时长，会漂 200+ 秒）。
⚠️ **并发不要超过 3** —— 并发 6 会撞限流，chunk 0 成片失败。

### 3.4 翻译 / 成分块标注（**要额度**）
用同伴会话的现成脚本：
```bash
python3 <shun>/tools/translate_zh.py --cues work/cues/<tag>_cues.json --out work/zh/<tag>_zh.json --shard 15
python3 <shun>/tools/gen_gs.py --ep <tag> --batch 4 --workers 3
```

## 四、🔴 验收红线（同伴会话定的，逐条都要过）

1. **`frame[].s` 必须逐字取自原句**（连续子串）—— 有一条不过就整条丢弃重生成。
2. **`blocks[i].s` 必须等于 `frame[i].s`**，数量一一对应。
3. **`b` 只能是 `[]` / `［］` / `〈〉` / `（）`** 四种，按**首字符**判类型（半角 `[` 与全角 `［` 是不同字符！）。
4. **`frame[].p` 区间**须在句内、长度相符、相邻不重叠。
5. ⭐ **合并率必须 = 0**（用户原话：「要分开不要一起」）：
   ```
   合并率 = (被合并的同类型相邻对) / 同类型相邻对总数
   ```
   基线：13 集人工验收过的数据里，同类型相邻占 32.9%（其中 73% 是 `〈〉` 宾语内容），
   **而合并率是 0** ⇒ 0 是可达成的，不是空标准。
   ⇒ 典型失败：`〈この家に〉〈しあわせを〉` 被合成 `〈この家にしあわせを〉`。

## 七、2026-10-25 同伴复核后的修正（已落地，零 API 调用）

同伴会话复核了本包的全部 147 个文件，抓出 3 类生成侧缺陷 + 1 个设计口径冲突。**全部已修**：

### 7.1 三类缺陷（根因同一个：`frame[].s` 不逐字）
| 症状 | 例子 | 修法 |
|---|---|---|
| s 里混进语义括号 | `s="［日本語を教えるの］が大好きですから"` | 剥掉括号（剥后仍是原句子串 ⇒ **修而不丢**） |
| 同义替换 | 原文「各々」写成「色々な」 | 不在原句里 ⇒ **丢弃该块** |
| 块越界 | 「本当にそうだなと」多吃了「と」 | 同上 ⇒ 丢弃 |

⇒ **新增闸门 `tools/frame_guard.py`**，已接进 `prod.py` 的生成链（`frame_problems.log` 记录每次丢弃/修复，不静默）。
⇒ **离线验证**（用已落盘的 7 集数据跑，零 API 调用）：497 帧 → 丢弃 2 / 修复 2 ⇒ 正好命中同伴报的 3 处。
⇒ **反向验证**：造坏样本（不逐字 + 括号混入）⇒ 必须 1 过 2 拒 ⇒ ✅。

### 7.2 设计口径冲突：〈〉 不许标状语
同伴的《shun/docs/新结构注释设计.md》定义四类固定语义：`[]`连接/副词 ｜ `［］`从句 ｜ `〈〉`**宾语内容** ｜ `（）`谓语。
而我产的 7 集里有 89 处把**状语**标成了 `〈〉`（例：`s="英語で", b="〈〉", role="状语"`）⇒ 会让用户误以为〈〉= 宾语。

⇒ **决定：按四类严格执行**（不扩第五类）⇒ 状语一律归入 `[]`。
⇒ 已在 `prod.py` 的 prompt 里写死（「〈〉 只标宾语；状语归 [] 或并进相邻块，不要自造第五类」），
   并在 `to_peer_format.py` 里做了**口径归一**（89 处已改）⇒ 转换器同时有 prompt 层和后处理层两道保险。

### 7.3 补上 `p` 字段（同伴的真实契约里有）
同伴线上 `shun-web/data/ep01.json` 的 `frame[]` 带 **`p: [start, end]`**（字符区间）⇒ 我原来的数据没有。
⇒ `to_peer_format.py` 已补（游标顺序推进，避免重复子串错位）。

### 7.4 顺手抓到一个新问题：从句整体块和它内部的成分块**重复覆盖**
例：`t="日本語を教えるのが大好きですから、…"` ⇒ frame 里有「日本語を教えるのが大好きですから」（［］从句整体）
**和**它内部的「日本語を」「教えるの」「が」「大好き」「ですから」（〈〉/[]）⇒ 同一段文字被覆盖两次。
⇒ `frame` 是**分层**语义，一层里不能同时出现外层和它的内部成分（与设计文档样例一致：
`frame=[しあわせの神様は(［］), この家に(〈〉), しあわせを(〈〉), 置きました(（）)]`）。
⇒ 修法：**外层优先** —— 被外层覆盖的内部块丢弃，共 6 处；**丢弃的块记进 `shun-web/frame_overlap.json`**（信息不丢，以后做 `blocks[].parts` 时可用）。

### 7.5 已按同伴契约产出 7 集（可直接铺）
`shun-web/data/s001.json` … `s361.json`，结构与同伴线上**逐字段一致**：
```
{tag, ep, title, desc, dur, audio, sents:[{t, ru, w, zh, gs:{frame:[{s,b,role,p}], src}, s, e}]}
```
- `ru` / `w`（逐字 ruby / 词）**留空** —— 同伴用本地 `ruby.py` + `kanjididic2` 算，零额度
- `gs` 只有 `frame` ⇒ 同伴的渲染层会自动降级（他已做好：「这一集只做了成分切分，没有逐块拆解。」）
- `audio` = redcircle 绝对直链
- `index.json` 由 `tools/merge_index.py` **compare-and-swap 合并**（拉线上 `{eps:[...]}` 当基底，只加我的 7 条，他的 13 集原样保留）
