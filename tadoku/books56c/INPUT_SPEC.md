# books56c 输入规格（推仓库前照这份写）

> 目的：书文件一推上来，我这边**立刻能跑**对齐 → 重建 → 验收，中间不来回改格式。
> 配套自检：`python3 tadoku/books56c/tools/check_books_input.py --books-dir <books 目录> --fetch-index`
> （自检脚本自证过：好数据必过 + 5 种坏法必被抓 + 「只有 seg」只报 WARN 不拦）

## 1. 文件与 tag
- 路径：`tadoku/books56c/books/<tag>.json`
- **`<tag>` == 文件名（去掉 .json）== 顶层 `tag` 字段 == manifest 里的 `tag`**（四处必须一模一样）

## 2. 顶层字段
```json
{
  "tag": "level0-...",
  "title": "一つ二つ三つ",
  "level": "Level Start",
  "dur": 145.53,
  "audio_mp3_all": ["9784866394701/Track01.mp3"],
  "cues": [ ... ]
}
```
- `dur`：**该书官方朗読音频的总时长（秒）**。口径以 `tadoku/books56c/asr_truth/index.json` 里该轨的 `dur`
  为准（那是官方 mp3 的 ffprobe 实测值），允许 ±0.5s；不一致会被自检拦下。
- `audio_mp3_all`：**相对官方音频包的路径**，格式与 `asr_truth/index.json` 的 `mp3` 字段**逐字同款**
  （例：`9784866394701/Track01.mp3`）⇒ 轨↔书是**机械对上**，不靠猜。
  一本书跨多轨 ⇒ 按数组顺序给出，我用**累计偏移**拼接（不物理拼音频）。
- `audio`（绝对 URL）可给可不给；我这边以 `audio_mp3_all` 为准。

## 3. 句子结构
```json
"cues": [
  { "s": 0.0, "e": 0.0,
    "rows": [
      { "t": "西町交番のりょうさん",
        "ru": [["西町交番", "にしまちこうばん"], ["の", ""], ["りょうさん", ""]],
        "zh": "西町交番的良先生" } ] }
]
```
- `cues[i].rows[j].t` = **纯正文，不带任何注音标记**（〈〉《》「」｜ 都不能进 `t`）。
  理由：我的对齐器把 `t` **逐字**当字符流去和 ASR 文字流比；注音标记会污染字符流。
- `ru` = **二维数组** `[[表层, 读音], ...]`，读音为空表示不注音。
  ⚠️ **线上 `app.js` 的 `rubyHtml()` 只认 `ru`**（`row.ru[i][0]` / `row.ru[i][1]`）；
  `seg`（`{base, rt}`）是**新格式，app 不认** ⇒ 要么同时给 `ru`，要么在生成 app 数据时把 `seg` 转成 `ru`，
  否则点句弹窗**没注音**。两份都在时**保持一致**（别让它们打架）。
- `zh` = 简体中文，**逐行**给（一行一句）。
- `s` / `e`：**可以先填 0**（我重算），但字段要在（我要按它们写 cue 顺序）。
- `w`（词解析）/ `blk`（中文块）/ `g`（句型）有就给，没有我这边不依赖。

## 4. 几条「已经踩过」的约定
- **制作信息行**（作／監修／原作／再話／簡約／NPO多言語多読…）：朗読里也念，但**不进正文**。
  要删就**按精确行内容**删，**不要按行号**（去重后行号会错位 ⇒ 会删错行）。
  删完请给我一份「删了哪几行 + 剩几行」的清单，我验收时逐条核。
- **「书上有、音频不念」的行**（例如唱歌页、练习题页）：**照留**。它们会在对齐里成为
  `no_audio`（哑句：保留正文、不参与高亮/跳转、时间轴归零）⇒ 这是**如实反映**，不是缺陷。
- 统计时我会把「书上有但音频没念」和「该念却没对上」**分开报**，别混成一个哑句数。

## 5. 推之前
1. 跑自检：`python3 tadoku/books56c/tools/check_books_input.py --books-dir <dir> --fetch-index` ⇒ 必须 rc=0
2. 推 `tadoku/books56c/books/*.json` + `tadoku/books56c/manifest.json`
3. 推裁决清单 `tadoku/batch1_decisions.json`（可审计、可复用）：
```json
{ "decisions": [
  { "id": "d001", "book": "<tag>", "where": "cue[31].rows[0]",
    "issue": "OCR 把「良」认成「长」",
    "candidates": ["良〈りょう〉", "长〈よし〉"],
    "evidence": "kanjidic2 + 印刷页图 + 官方朗読",
    "ruling": "良〈りょう〉", "by": "构建会话", "at": "2026-10-25" } ] }
```
（`where` 必须能定位到具体文件的具体行 ⇒ 清单才可复现、可回滚）
