# 墨水屏描边闸门（check_eink_css）—— v4.4

电子墨水屏（黑白）上，**纯黑描边会糊成一排粗杠杠**。半透明边框 `rgba(0,0,0,.35)`
在墨水屏上才是「一条细线」。

**两份实现，口径逐条一致、输出逐字一致，可互换使用：**
- `check_eink_css.js` —— Node，零依赖
- `check_eink_css.py` —— Python 3，零依赖

> v3 是「口径一致」；**v4 起是「输出逐字一致」** —— 同一批样本跑两份实现，
> stdout 必须**逐字相同**（不只是抓的行号相同）。
> 验证方式见下面「跨实现对拍」。

```bash
# 检查（违规 exit 1）
node check_eink_css.js web/*.css
python3 check_eink_css.py web/*.css

# 自动修（改完回读复检；修不了的会如实报告并仍 exit 1）
node check_eink_css.js --fix web/*.css
python3 check_eink_css.py --fix web/*.css

# 结构线名额可配（v4 起 JS 版也支持，v3 只有 Python 版支持）
node check_eink_css.js --max-structure 2 web/*.css
python3 check_eink_css.py --max-structure 2 web/*.css

# 机器可读输出（v4 新增，两份实现 JSON 逐字一致）
node check_eink_css.js --json web/*.css
python3 check_eink_css.py --json web/*.css

# 亮度阈值可配（v4.4 新增）
node check_eink_css.js --max-dark 0.08 --max-mid 0.25 web/*.css
python3 check_eink_css.py --max-dark 0.08 --max-mid 0.25 web/*.css
```

🔴 **v4.4 起可以直接传 .html** —— 内联 `<style>` 块里的违规也会被扫到
（很多项目把主题变量内联在 HTML 里，只扫 .css = 完全扫不到）。

## 🔴 必须把 css **和 html** 一起传
v4.4 起变量表**按页面分组**（见下节）：每个 html = 一个页面组 = {该 html} ∪ {它引用的 css}。

```bash
# ✅ 对：html + css 一起传（按页面分组，最准）
node check_eink_css.js web/index.html web/*/index.html web/shell/*.css web/*/*.css

# ⚠️ 只有 css 没有 html → 退回「跨文件合并」→ 多页面站里同名变量会互相污染
node check_eink_css.js web/*/*.css

# ❌ 错：只传一个 css → 变量解析不出 → 一片 FAIL
node check_eink_css.js web/dora/style.css
```

> 单文件 css 用 `var(--x)` 引用别处定义的变量时，**必须连 html 一起传**。

## 判定口径
🔴 **v4.4 的判据是二维的：亮度 × 宽度**（不是只看字面量纯黑）

| 情况 | 处理 |
|---|---|
| **纯黑级**（亮度 ≤ 8%，约 `#141414` 以内）—— 任何宽度 | ❌ 违规（墨水屏上等同纯黑） |
| **深色级**（亮度 ≤ 25%）+ **四边框** + 宽度 ≥ 2px | ❌ 违规（粗框会糊成杠杠） |
| 深色级但**只有 1px**（细线） | ✅ 放行（细线不是粗杠杠） |
| 深色级但是**单边**（`border-left` 等，只是分隔线） | ✅ 放行 |
| `border-bottom` 实黑 | ✅ 豁免（结构线），但**只数实黑的**、计入名额（默认 ≤2） |
| **半透明**（`rgba(0,0,0,.35)`） | ✅ 放行（淡线；**alpha < 1 一律不算**） |
| `var(--fg)`（解析变量链 `--fg → var(--sh-fg) → 值`）指向硬色 | ❌ 违规 |
| **同名变量多定义**（多主题） | 任一定义解出硬色 → ❌ 违规 |
| `border: 1px solid #000, var(--x)` | 取**第一个具体色** → ❌ 违规 |
| `border: 1px solid var(--x, #eee)` 且 `--x` 未定义 | 用 fallback `#eee` → ✅ 不违规 |
| `black` / `#000` / `#000000` / `rgb(0,0,0)` / `rgba(0,0,0,1)` | ❌ 违规 |
| **`#000 !important`** | ❌ 违规（**先剥掉 `!important` 再判色**） |
| **小数宽度**（`border:1.5px solid …`） | ✅ 也能扫到（v4.1 之前**静默漏检**） |
| `currentColor` | ❌ 违规（解析不了） |
| 变量**解析不出来**（且无 fallback） | ❌ 违规（不是放行） |
| 主题色 / `inherit` / 合法变量（如 `--ink: #1a1a1a` 当 **color** 用） | ✅ 不动 |
| 该行含 `eink-ok:` 标记（同行或上一行） | ✅ 豁免（各站自己解释例外） |

> ⚠️ **「墨水屏是二值的」这个前提不严谨** —— 实际是 16 级灰度，深灰会显示成深灰。
> 真正扎眼的是「**纯黑级 + 粗**」，不是「所有深色」。
> v4.4 的阈值就是按这个定的：`--max-dark 0.08` / `--max-mid 0.25`。

## 豁免机制
```css
/* eink-ok: 当前句位置指示竖条 —— 设计要求：不用变色（用户 2026-10-22 明确），只用左侧竖条 */
.cur { border-left: 6px solid #000 !important; }
```
比黑名单好：各站能自己解释自己的例外，review 时一眼看到「为什么这条可以留」。

## 🟢 自检：闸门本身要能被验证

```bash
python3 test_eink_gate.py        # 101 项，全绿才算过
python3 test_eink_gate.py -v     # 打印每项明细
```

**九组**：

| 组 | 验什么 |
|---|---|
| **A** 正向 | 已知违规样本 → 必须抓到，且**行号完全一致**（11 条）+ 三种原因都报 + 豁免行不误报 + 合法行不误报 |
| **B** 反向 | 已知合法样本 → **必须判干净**（exit 0、无 FAIL） |
| **C** 跨实现对拍 | JS / PY 的 **stdout 逐字一致** + `--json` 逐字一致 |
| **D** 闸门有效性 | 把判色函数改成恒 false / 恒 true → 结果必须跟着变；文件不存在 → 必须 exit 1 |
| **E** 真实 css | 拿真的 `ai-client.css` 跑 → 不误报 |
| **E2** **真实链路** | 拿**真的** css **改坏一字节** → 必须被拦住（不能只在自检里自证） |
| **G** **v4.4 的四个洞** | 近黑 / 小数 px / HTML 内联 / 半透明误判 —— 每个都有正反两向 |
| **F** **自检的有效性** | 把闸门改坏（4 种形态）→ **本自检必须红** |

### 🔴🔴 为什么 E2 组不能省（NHK 提的，我照做）
> 「闸门能不能拦住必须在**真实链路**上验，不能在自检里自证。」

理由：自检是「**我**造的样本 ↔ **我**写的判据」→ 两边都是我写的，容易一起错。
拿**真实项目的 css** 改坏一字节再跑 → 才验证了「闸门在真实输入上真的拦得住」。

### 🔴🔴 为什么 B 组和 F 组不能省

**B 组（反向）**：「已知违规 → 必须抓到」这一侧**不够** ——
一个恒返回「没有违规」的空实现也能通过那个测试。
必须再有「**已知合法 → 必须判干净**」这一侧。
（这条是 API 闸门 v4 的教训：我的反向用例原本只拆了**第一个**守卫，
而真实 APK 有 10 个 → 样本假设错 → 自检看着像坏了。）

**F 组**：光看「自检全绿」不能证明自检有效 —— 闸门被改松了，自检也该红。
4 种改坏形态：
1. 判黑失明（`isPureBlack` 恒 false）
2. 过度敏感（`isPureBlack` 恒 true）
3. **变量解析不出就放行**（最阴险的静默失真）
4. 不剥 `!important`（漏检变体）

### 🔴🔴🔴 「子进程 returncode != 0」**不等于**「自检抓到了」
F 组最初只断言子进程退出码非 0 → 实测**假绿**：
子进程因为 `FileNotFoundError` **崩溃**退出，退出码也是 1 → F 组照样「通过」，
但它什么都没证明。
⇒ 现在 F 组要求子进程**正常跑完**（输出里有收尾汇总行）**且确实有失败项**。

> 这条比 bug 本身值钱：**崩溃 ≠ 测试红**。
> 跟「工具的 bug 会直接变成结论」是同一个病根。

## 七条铁律
1. **闸门必须接进打包流程**（`build-apk.js` 里调用，违规 `die()` 拒绝出包）——
   「自测抓不到的东西，必须变成构建期硬失败」。
2. **闸门本身要能被验证**：写完故意造一份违规样本跑一遍，确认它真拦得住。
3. **造样本要覆盖「修不了的那类」**（解析不出的 var / currentColor）——
   那正是让 `--fix` 静默失败的那类。
4. **路径写错 / 文件不存在 → FAIL**，不能「跳过 + 放行」（那是假绿灯）。
5. **跳过分支必须打日志**（「已存在就跳过」不打日志 → 跳过和处理了长得一样）。
6. **自检必须正反两向**：已知违规 → 抓得到 **且** 已知合法 → 判得干净。
7. **「测试红」≠「进程崩了」**：断言自检有效性时，要看**汇总行**，不要只看退出码。
8. **判断和提取必须用同一套逻辑** —— 否则「只测到开标签」会把**只在注释里提到
   `<style` 的 .css** 误判成 HTML → 整份 css 被抽成空壳 → **一条违规都扫不到**。
9. **给正则加捕获组后，要检查用到它的每一处** —— 脚本的全局替换会把**所有**匹配处一起改。

## 🔴🔴 v4.4 最重要的一条：变量表**按页面分组**

**CSS 语义：变量在同一个文档内解析。同名变量在不同页面里是无关的。**

实测踩到的（hub v1.11）：
- hub = 总目录 `index.html`（自己内联 `--line:#111`）+ 6 个项目子页
- 老实现把**所有文件**的变量合并成一张表
  → 总目录的 `--line:#111` 污染所有项目的 `var(--line)`
  → **一次扫描 93 条，其中 80 条是假的**（真问题只有 13 条）
  → 维护者会照着改一堆不需要改的地方

v4.4 的规则：
| 情况 | 行为 |
|---|---|
| 传了 html | 每个 html = 一个页面组 = {该 html} ∪ {它引用的 css（按引用顺序）} |
| 一个 css 被多个页面引用 | **每个页面各判一次**，结果合并（去重） |
| 没被任何 html 引用的 css | 自己单独一组 |
| **没传 html** | 退回「跨文件合并」（旧行为）→ 输出会**提示**你把 html 一起传 |

> ⚠️ **扫多页面站点必须把 html 一起传**，否则同名变量互相污染。

配套修的三个洞（都在这一版）：
1. **注释里的变量定义会污染变量表** —— hub 的 sakura/style.css 注释里写着
   「它的 `--line:#000000` 还会污染跨文件合并的变量表」→ 闸门把这条**注释里的**
   定义当真了 → 大量误报。⇒ 现在读文件时**等长剥注释**（行号/偏移不变）。
2. **`readForScan` 判断和提取不一致** —— 用「有没有 `<style`」判断、用「有闭合标签」提取
   → 一份**只在注释里提到 `<style` 的 .css** 被误判成 HTML → 整份 css 被抽成空壳
   → **一条违规都扫不到**（假绿灯）。
3. **豁免标记被剥注释误伤** —— 「在上一行注释里写 `eink-ok: 理由`」是正常用法
   （ai-client.css 就这么写）⇒ 现在**变量收集/边框匹配**用剥注释后的文本，
   **豁免判定**用原文。

## 写这类闸门的通用坑（跨项目复用）
1. **fallback 拆分必须只按「顶层逗号」切** —— 颜色自身带逗号（`rgb(0,0,0)`）→ 硬切变 `'rgb(0'` → 漏检。
2. **`--fix` 的回滚条件是「修复让情况变差」，不是「还有问题」** ——
   剩下那几条（var 解析不出 / currentColor）**本来就修不了** →
   「只要还剩问题就整份回滚」会把**已修好的也撤销** → `--fix` 永远 0 处。
3. **`String.replace` 回调里 `match.index` 是 undefined** —— 只能用第 5 个参数 `offset`。
4. **块注释里不能写完整的注释结束符** —— 结束符会把块注释提前闭合 → `node --check` 报语法错。
5. **`!important` 要先剥掉再判色** —— 否则颜色捕获成 `'#000 !important'` → 漏检。
6. **同名变量要存成 list**，不能覆盖式收集 —— 多主题场景会漏检。
7. **JS 有 `const` 的 TDZ**：变量声明必须在使用分支**之前**。
